# ATK-DNESP32S3-BOX2-WIFI USB 语音输入终端

同一份固件提供 **USB 语音输入终端** 和 **普通 USB Serial/JTAG 串口** 两种模式，
适配 ESP32-S3 BOX2 WIFI、ES8389 麦克风和 240×320 显示屏。
通用硬件驱动放在 `driver`，应用与 USB 代码放在 `main`。

语音输入终端模式是一个 **复合 USB 设备**：UAC 麦克风 + HID 键盘。
开始输入有两种方式：短按 M，或直接说唤醒词「Hi 乐鑫」。
设备先播放提示音，再向电脑发送一个可配置快捷键（默认 `Ctrl+D`），
然后才打开麦克风；结束输入时关闭麦克风并再次发送快捷键——按键和唤醒词
走的是同一条代码路径，行为完全一致。
这样任何支持语音快捷键的应用都能被设备直接唤起，不需要先点窗口和麦克风按钮。

应用使用独立的中文日常界面：麦克风页显示连接、聆听、电平、增益和电量；
串口页显示连接状态和模式切换提示。

## 按键

| 状态 | 操作 | 功能 |
|---|---|---|
| 开机，两种模式 | Q 长按 2 秒后松开 | 保存模式，重启切换麦克风 / 普通串口 |
| 开机，两种模式 | M 长按 2 秒后松开 | 关机；屏幕显示长按进度和松开提示 |
| 关机 / USB 待机 | M 短按后松开 | 开机，恢复之前保存的 USB 模式 |
| 麦克风模式 | 短按 M 后松开 | 开始 / 结束语音输入，并发送电脑快捷键 |
| 麦克风模式 | 说「Hi 乐鑫」 | 开始语音输入（等同短按 M） |
| 麦克风模式 | 说完停顿 2 秒 | 自动结束语音输入 |
| 麦克风模式 | L / R 短按 | 输入增益降低 / 提高 3 dB |

长按 M 不会同时触发短按说话；关机手势松开也不会立即唤醒。
Q 和 M 均去抖，完成长按后等待按键稳定松开，避免重启时仍按住按键。
开机按住 M 的首次手势会被忽略，松开后再进行正常操作。
上电时请松开 Q/L/R，这三个按键仍会标定空闲电平；M 使用原板规定的高电平有效逻辑。
R 同时是 BOOT（GPIO0），只在按下时读取，不用于长按手势。

首次烧录且 NVS 没有模式记录时，默认进入 **普通串口模式**。
模式保存在 NVS，断电和 M 开关机后保留。增益默认 30 dB，范围 0～42 dB；
增益在重新开机时恢复默认值，语音输入状态每次开机都从关闭开始。

## 语音输入的工作方式

麦克风在空闲时**不送出信号**：UAC 流可以一直开着，但设备未在输入时只填零。
开始输入后顺序是「提示音 → 打开麦克风 → 发送快捷键」，因此提示音不会进入录音。

### 语音唤醒

麦克风一直在采：唤醒词检测需要电脑没有开麦时也有音频，所以采集从 USB 回调里
独立出来，变成常驻任务（`main/mic_stream.c`）。48 kHz 数据进环形缓冲供 USB 取用，
同时经 4 阶巴特沃斯低通抽取成 16 kHz 送给 esp-sr 的前端。

- 唤醒词固定为 **Hi 乐鑫**（`wn10_hilexin_int16`，模型在 `model` 分区）。
  esp-sr 只提供固定词表，自定义唤醒词要走乐鑫的定制或 TTS 训练，改代码解决不了。
- 结束方式用**静音断句**而不是命令词：说「结束」会被 ASR 一起转写进文本，
  日常说话也容易误触发。规则是「检测到说话后，再连续 2 秒静音」；
  唤醒后 6 秒一直没说话也会自动结束，避免占着电脑的麦克风不放。
- 提示音和唤醒词尾音期间会屏蔽检测 700 ms，否则喇叭就在麦克风旁边，
  会自己把自己唤醒。
- 唤醒词检测的 CPU 占用不低，唤醒任务钉在 core 1、USB 在 core 0，
  所以录音不会因为跑模型而周期卡顿。
- 短按 M 仍然有效，两条入口共用同一段开始 / 结束代码。

改动模型或 `partitions.csv` 后必须 `idf.py flash`（不是 `app-flash`），
否则模型分区不会被重写。

默认快捷键是 `Ctrl+D`（多数 AI 语音输入 / 对话应用的默认唤起键），
对应 `tap` 模式。换成一个应用自己的快捷键即可复用同一块设备，例如
`ptt ctrl+alt+space`。若使用需要「按住说话」的应用，改成 `hold` 模式：
按下时按下按键，松开时释放。注意 `hold` 模式按住期间系统会重复触发按键，
只适用于显式区分按下 / 松开的应用。

快捷键和模式保存在 NVS，只能在串口模式修改（语音输入模式下没有控制台）。

语音输入进行中按住 M 不会关机：说话时按住按键是自然动作，长按关机只在
语音输入关闭时生效。要关机先按一次 M 结束输入，再长按 2 秒。


## 关机与外部供电

固件在松开 M 后停止 USB 音频采集、断开电脑 USB 设备、关闭背光和扬声器，
停止电池采样，再按原板顺序将 CHG_CTRL 拉低、释放 SYS_POW 电源锁存。

电池供电使用板上的硬件断电路径，再次按 M 由硬件启动。
**插着 USB 时，外部电源可能继续供电**：若 CPU 仍在运行，固件进入黑屏、
USB 已断开的软件待机，只处理下一次短按 M；随后重新锁存供电并重启到已保存模式。
这是功能待机，没有进入 ESP 深度睡眠，也不能让电脑的 USB 供电线路物理断电。

固件不使用充电状态 CHRG 判断能否关机，因为充满电后该信号不能代表 USB 是否拔出。
关机期间不采电池，避免电池采样重新配置 CHG_CTRL、影响电源锁存。

## 语音输入终端使用

1. 用支持数据传输的 USB 线连接设备和电脑。
2. 在串口模式长按 Q 2 秒，看到松开提示后松开。
3. Windows 会把设备识别为 `BOX2 Microphone`（音频输入）和 `HID Keyboard Device`
   （键盘），两个都在同一个 USB 设备下，不需要装驱动。
4. 先把光标放进目标应用的输入框，屏幕显示“准备就绪”。
5. 开始输入，两种方式任选：短按 M，或直接说「Hi 乐鑫」。
   听到提示音、屏幕变为“正在录音”，设备向电脑发送 `Ctrl+D`。
6. 结束输入：说完停顿 2 秒自动结束，或再按一次 M。
   麦克风关闭并再发一次 `Ctrl+D`。
7. L/R 调整增益；长按 Q 后松开返回普通串口。

录音格式固定 **48 kHz / 16 bit / 单声道**。使用 ES8389 左路麦克风输入，
连续去除直流偏置后写入环形缓冲，USB 侧按主机的 10 ms 节奏取走，
再由 TinyUSB FIFO 传给电脑。采集由 I2S/DMA 时钟驱动、USB 由主机 SOF 驱动，
两者之间的漂移靠 1 ms 粒度水位修正吸收，不再出现长录音累积丢帧。

采集**始终运行**（唤醒词需要），但未在输入时设备仍然保持 UAC 流并只发送零值，
所以应用里显示的输入电平为 0。空闲期间环形缓冲会被丢弃，
因此打开麦克风的瞬间不会把之前的房间声音补送给应用。
增益通过实体键调整，USB 控制只提供主声道静音。

提示音走 ES8389 扬声器通路，只在播放时打开 PA。提示音在麦克风打开之前播放，
不会被录入。扬声器音量固定，没有对外接口。

喇叭必须按**双声道**驱动：`no_dac_ref = false` 时 ES8389 从第二个槽取 DAC 参考，
只发单声道左槽会把参考拉到 0，输出变成直流台阶，功放一开关就是一声爆响。
因此 I2S TX 配置为立体声、左右写入同一样本，且功放在静音状态下开关，
音量在开关之后才抬起（`driver/box2_audio.c`、`main/device_tone.c`）。

帧缓冲在 PSRAM，但送屏时不直接交给 DMA：整帧 153 KB 的突发会和缓存抢外部内存，
画面静止时读到旧帧看不出来，内容一变就是花屏。屏幕现在按 16 行一条、
经内部 RAM 的中转缓冲发送，并且只在状态真的变化时才重绘。

串口模式保留日志、命令、下载和调试功能，发送文本命令即可：

```text
usb mic        保存麦克风模式并重启
usb serial     保持普通串口模式
usb status     查看当前模式
ptt            查看当前快捷键和模式
ptt ctrl+d     设置快捷键（默认 ctrl+d）
ptt mode tap   一次按键开始 / 结束，适合切换式快捷键
ptt mode hold  按下时按下按键，松开时释放
ptt off        不再发送任何按键
beep           播放提示音（仅麦克风模式）
help           查看命令说明
```


支持 CR、LF、CRLF 换行。关机阶段禁用并丢弃串口命令。
麦克风模式没有 COM 端口，返回串口使用 Q 键。

两种模式共用 S3 的内部 USB PHY，退出麦克风和启动时显式恢复串口通路；
不需要修改 eFuse。麦克风发生 panic 或看门狗复位时，固件尝试恢复串口模式，
方便下载调试。普通 RESET、开机和正常切换保留所选模式。

## 构建与烧录

使用 **ESP-IDF 6.0.2**，芯片 ESP32-S3，16 MB Flash，8 MB OPI PSRAM。
应用固定依赖 `usb_device_uac 1.3.1`、`tinyusb 0.19.0~3` 和 `esp_codec_dev 1.6.2`。

```powershell
idf.py build
idf.py -p COMx flash
```

将 `COMx` 替换为设备的实际串口号；烧录前用 Q 切回普通串口模式。
首次烧录使用 `flash` 写入引导程序、分区表和应用；后续应用更新可使用 `app-flash`。

UAC 原始仅麦克风描述符声明了实际控制数组不支持的声道 1 控制。
`main/usb_descriptors.c` 保留原许可并修正声明，构建只替换描述符源文件，
不修改 `managed_components`。升级 USB 组件时需要核对控制回调和描述符。

同一个文件还补上了 HID 键盘接口（接口 2、端点 0x83、63 字节报表），
配置描述符总长和接口数由 `ITF_NUM_ALL` 计算。`usb_device_uac` 提供的
`tusb_config.h` 不打开 HID，所以 `main/CMakeLists.txt` 用
`target_compile_definitions(... PUBLIC CFG_TUD_HID=1)` 打开。
这个定义必须同时作用于 `usbd.c`、`hid_device.c` 和 `main`，否则描述符会声明一个
没有驱动支撑的接口，表现为设备无法枚举或键盘无响应。

`build/esp32_box2.bin` 是应用镜像，地址 `0x10000`。
`build/esp32_box2_full.bin` 是包含引导程序、分区表和应用的合并镜像，地址 `0x0`。
更新建议使用 `idf.py app-flash`，或将应用镜像写到 `0x10000`，以保留 NVS 和已保存模式。
完整合并镜像从 `0x0` 连续写入，会覆盖 NVS 间隙，已保存模式将重置为默认串口。

## 故障恢复

若无法正常启动，用 BOOT（GPIO0 / 最右 R 键）配合 RESET 进入 ROM 下载模式后烧录。
麦克风模式没有串口端口，正常更新时先长按 Q 后松开，返回普通串口模式。

电脑端以 Windows 为目标。

## 驱动库

`driver` 可复制到其他 ESP-IDF 工程，通过 `EXTRA_COMPONENT_DIRS` 注册，
在应用 `PRIV_REQUIRES` 添加 `driver`，统一包含 `box2.h`。

- `box2_board_*`：共享 I2C、TCA9555、按键、电池、电源锁存和扬声器开关。
- `box2_audio_*`：PCM 采集/播放、输出音量、输入增益和采样率。
- `box2_lcd_*`：LCD 初始化、背光和 RGB565 位图绘制。
- `box2_motion_*`：SC7A20 初始化和三轴采样。
- `box2_storage_*`：TF 卡挂载、容量查询和卸载。

正式界面使用 `main/device_screen.*`，按键手势使用 `main/device_controls.*`，
快捷键配置与 HID 上报使用 `main/usb_hid.*`，提示音使用 `main/device_tone.*`。

`main/device_tone.c` 的提示音在调用者任务里同步播放，占用约 160 ms 并持有
TCA9555 的输出互斥锁，不要从 UAC 采集回调调用。

ES8389、SC7A20、TCA9555 共用 I2C GPIO48/47，7 位地址为 `0x10`、`0x19`、`0x20`。
USB 使用 S3 原生 GPIO19/20。LCD 使用 8 位 I80 总线，帧缓冲在 PSRAM。
电池电量根据 BOX2 原板 ADC 标定表估算。

电源锁存和 M 极性参考
[BOX2 原板实现](https://github.com/78/xiaozhi-esp32/blob/main/main/boards/alientek/atk-dnesp32s3-box2-wifi/atk_dnesp32s3_box2.cc)。
